# AGENTS.md

Conventions for AI coding agents (and anyone else) working in this repo. See
[SPEC.md](SPEC.md) for the full technical design and rationale, and
[README.md](README.md) for setup/usage commands.

## Hard constraints — do not cross these

- **Testnet only.** Never add a mainnet deployment path, mainnet RPC config,
  or mainnet-targeting script. This project's entire premise is that it holds
  no real value.
- **Never commit or print real secrets.** `PRIVATE_KEY` (Sepolia testnet key),
  `SEPOLIA_RPC_URL`, `ETHERSCAN_API_KEY` live in `.env` (gitignored) and
  `frontend/.env.local` (gitignored). Never ask a user to paste a private key
  into chat — have them set it directly in their local `.env`.
- **Fake eligibility data only** (`merkle/eligibility.json`). Do not replace
  it with real addresses or wire this up to any real distribution.
- **Commits should not include a `Co-Authored-By: Claude` (or similar AI
  co-author) trailer** — explicit standing preference for this repo.
- **Commit messages use a Conventional Commits prefix** (`feat:`, `fix:`,
  `chore:`, `docs:`, `ci:`, etc.) — explicit standing preference for this
  repo.

## Repo layout

| Path | What |
|---|---|
| `src/` | Solidity contracts (`TestToken.sol`, `MerkleAirdrop.sol`) |
| `test/` | Foundry tests |
| `script/` | Foundry deploy scripts (Sepolia) |
| `merkle/` | Script generating the merkle tree from fake eligibility data (run with Bun) |
| `lib/` | `forge-std` and `openzeppelin-contracts`, vendored as plain files (installed with `--no-git`, so no submodules — they're tracked directly) |
| `frontend/` | React + Vite + TanStack Router + wagmi/viem + shadcn/ui claim page |

## Build / test loop

```shell
forge build
forge test -vv
```

If a contract change touches `MerkleAirdrop.sol`'s leaf/proof logic, re-run
`bun run generate` in `merkle/` and update the pasted-in root/proof constants
in `test/MerkleAirdrop.t.sol` to match — they're hardcoded from a specific
generated tree, not derived at test time.

Frontend:

```shell
cd frontend && bun run build   # tsc -b && vite build — must pass with no type errors
```

If contract ABIs change, regenerate `frontend/src/abi/*.json` from
`out/<Contract>.sol/<Contract>.json` (the `.abi` field) rather than
hand-editing them.

## Known gotchas

- **Double-hashing convention**: OZ's `MerkleProof.verify` expects leaves as
  `keccak256(bytes.concat(keccak256(abi.encode(account, amount))))`. This must
  match exactly between `MerkleAirdrop.sol` and `generate-merkle-tree.mjs`, or
  valid proofs get rejected. Use `@openzeppelin/merkle-tree`'s
  `StandardMerkleTree` — it produces this format automatically. Don't switch
  to `merkletreejs` without re-deriving this by hand.
- **`vm.readFile` in `DeployAirdrop.s.sol`** requires the `fs_permissions`
  entry in `foundry.toml` (`{ access = "read", path = "merkle/output" }`). If
  that script starts failing with a permissions error after a `foundry.toml`
  edit, check that entry wasn't dropped.
- **`frontend/src/routeTree.gen.ts`** is auto-generated by the TanStack Router
  Vite plugin (gitignored) — don't hand-edit it, and don't be surprised it's
  regenerated on `bun run dev` / `bun run build`.
- The `tanstackRouter()` Vite plugin must be listed **before** `react()` in
  `frontend/vite.config.ts`.
- **Package manager is Bun, not npm** — both `merkle/` and `frontend/` use
  `bun.lock` (tracked in git). Don't reintroduce `package-lock.json` or run
  `npm install`; if you add a dependency, use `bun add`.
- **CI** (`.github/workflows/ci.yml`) has three jobs: `contracts` (forge fmt
  check, build, test), `frontend` (bun install --frozen-lockfile, typecheck,
  lint, audit, build), `merkle` (install --frozen-lockfile, audit, smoke-run
  the generator). Audit is gated at `--audit-level=high` rather than default —
  there's a known moderate-severity advisory in a transitive dependency of the
  `shadcn` CLI (a dev-time-only tool, not shipped app code); don't lower this
  threshold to silence it, and don't raise it to `critical` without checking
  why first.
